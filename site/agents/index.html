LOCAL CONFIGURATION BUILDER

Create your MCP client configuration

Nothing is sent, saved or tracked by this helper. It does not ask for API keys.

Install Node.js 22+, clone the public repository and use its local checkout path. Windows paths like C:\Users\you\24GO.top are supported.

The MCP_AGENT_PACKAGE path and other local file paths identify private local files from the offline signing workflow. Do not enter file contents, secret keys or GitHub tokens. Keep the signed manuscript outside your public Git checkout.

Private authoring: this MCP sends one article brief and evidence package to the model endpoint you configure. It requires explicit per-call cost and provider-data consent, then saves a private signed manuscript outside the Git checkout. It does not upload the manuscript or create a public PR. For remote providers, inject AGENT_DRAFT_KEY through your MCP host's protected secret manager; never paste it here.

Only HTTPS endpoints or HTTP loopback inference are accepted. The writer and optional reviewer API keys are deliberately not collected or included in the generated config. The server allows one generation request and, if configured, one separate review request per process; failed or ambiguous requests are never retried.

The tool requires a clean `main` checkout, pins its source SHA before generation and checks it again afterwards. If a second model is configured, the agent can call `review_article_draft` after writing; it returns advisory findings and stores a private report. Both calls require separate cost and provider-data consent. The writer can then call `revise_article_draft` with revised Markdown; the local key re-signs one private revision and produces a new publication digest without another model request. It returns the private file paths and exact publication digest. Inspect the full draft.md, signed package, summary and receipt locally. Only then configure the separate publication MCP with the exact digest and a least-privilege GitHub token.

Public-content warning: after separate operator opt-in, the complete manuscript and generated static assets become public in a DRAFT GitHub PR. The generated configuration below is preview-only and sets MCP_AGENT_ALLOW_PUBLIC_PR=0. After reviewing the exact package digest, change that flag to 1 in your local MCP configuration and inject the approved digest and fine-grained token through a protected local secret manager. The browser helper never handles credentials.

Exact format: YYYY-MM-DDTHH:mm:ssZ. Refresh the PR if the release is delayed more than 24 hours.

The local process requires a clean checkout on main that exactly matches remote main. It creates a DRAFT PR only; human review, merge, green CI and HTTPS release verification are still required.

JavaScript is required to generate the configuration. No network submission is possible.



Paste the generated mcpServers entry into a compatible local MCP client's configuration. Client-specific settings vary; restart the client after installation. The configuration only starts a local process and does not connect or register an agent on the hosted website.


The authoring integration performs one configured BYOK generation and keeps all draft files local. The separate publication process uploads the full manuscript to a public DRAFT PR only after a separate exact-digest approval and a repository-scoped token; it never merges or deploys. Read the article publication operator runbook before enabling writes.






How an article reaches the public site


A connected agent can generate one private article through the BYOK authoring MCP, then a second advisory model can review its signed manuscript. A human editor checks claims, sources and rights. An Issue remains a proposal; the new publication MCP can create a complete static article DRAFT PR with all discovery assets. The article reaches the public site only after human review, merge, green CI and verified GitHub Pages HTTPS delivery.
